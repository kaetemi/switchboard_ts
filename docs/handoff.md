## 3. How to run everything

```sh
npm ci                                    # in a worktree: node_modules is a symlink to the main checkout's; do not install there
npm run check                             # biome, tsc (src), unit + integration projects
npx tsc -p tsconfig.test.json --noEmit    # type-checks test/** too; CI does not run it
npm run build                             # dist/ for the four entry points
npx vitest run --project unit test/unit/mux   # one directory, fast
```

**Native QUIC.** `npm run build:native` builds the addon with cargo into `native/sbq-node.node` (about three minutes cold; Rust 1.99.0 in CI, 1.88 or later needed); or set `SWITCHBOARD_QUIC_ADDON=<file>` to one already built. The native files then run with the others; on their own: `npx vitest run --project integration test/integration/quic-native.test.ts test/integration/quic-binding-native.test.ts test/integration/quic-node-native.test.ts test/integration/review-quic-native.test.ts test/integration/node-quic.test.ts test/integration/node-webtransport.test.ts test/integration/identity.test.ts`. Without the addon they skip with a reason; `SWITCHBOARD_NATIVE=required` fails instead (CI). `node tool/sync-sbq.mjs --check <switchboard_quic checkout>` verifies the vendored shim against the pin.

**Browser.** `SWITCHBOARD_BROWSER=required npm run test:browser` (its own config, `test/browser/vitest.config.ts`): the addon for the native WebTransport listeners, the `playwright` dev dependency (1.64.1) and its Chromium and Firefox (`PLAYWRIGHT_BROWSERS_PATH`); Vite serves the page from the sources. `SWITCHBOARD_BROWSER_LOG=1` prints the page's log.

**Interop.** `npm run test:interop` needs a Dart SDK 3.13.5 (`dart` on PATH, `SWITCHBOARD_DART_SDK`, or `node tool/dart-peer.mjs build --download-sdk`), a Rust toolchain (the Dart QUIC package's build hook runs cargo) and the two Dart repositories (sibling checkouts, `SWITCHBOARD_DART_CORE` and `SWITCHBOARD_DART_QUIC`, or `node tool/dart-peer.mjs fetch`). The global setup builds the AOT peer once and caches it on a stamp (`node tool/dart-peer.mjs status`); `SWITCHBOARD_DART_PEER=<exe>` uses a prebuilt peer (from a worktree, the main checkout's, built at the pins), `SWITCHBOARD_INTEROP=required` fails without a peer (CI), `SWITCHBOARD_INTEROP=skip` skips without looking, `SWITCHBOARD_TS_PEER_RUNTIME=<executable>` runs the TS peer on another runtime (`bun`; the whole project passes with it, `docs/notes/interop.md` section 13; the Dart driver still spawns the TS peer with `node`), `SWITCHBOARD_FUZZ_SEED` and `SWITCHBOARD_FUZZ_COUNT` replay or widen the oracle.

**Bun and Deno**, with the built package (a consumer project whose `node_modules/@kaetemi/switchboard` points at the repository, `ws` installed beside it):

```sh
bun run test:unit                         # what CI runs on Bun
bun app.ts                                # a script importing @kaetemi/switchboard/node
deno run --allow-net --allow-read --allow-env --allow-ffi app.js
```

Deno needs `--allow-ffi` for the addon (and `--allow-read --allow-env` for its loader), and `ws` in a `node_modules` directory for the WebSocket server (`--node-modules-dir=manual` for a lone script). Node 22 runs compiled JavaScript; its type stripping cannot parse `await using`, so TypeScript using it runs on Node 24+ or after `tsc`.

**CI** (`.github/workflows/ci.yml`): lint and typecheck; unit and integration on Node 22, 24 and 26; the unit project on Bun; build (and an import of `dist/`); `interop` (Dart peer, required mode; then the matrix again with the TS peer on Bun, `SWITCHBOARD_TS_PEER_RUNTIME=bun`); `native` (addon build after `sync-sbq --check`, the native QUIC files); `browser` (addon build, Playwright's Chromium and Firefox, `npm run test:browser` in required mode); `deno` (the unit and integration projects on Deno 2.9, and the built package installed from its tarballs through `test/runtime/smoke.mjs`).

## 5. Decisions

The design's section 11 is the list; the ones a session meets first:

- **Package** `@kaetemi/switchboard`; prebuilt addons `@kaetemi/switchboard-quic-<target>` as optional dependencies of the published package (Linux x64 and arm64, glibc and musl; macOS arm64 and x64; Windows x64), added by `tool/prebuilt-deps.mjs --apply` in the release workflow's pack step and not listed in the repository's `package.json` until they are published (npm 11 refuses `npm ci` with a lock file that cannot resolve them; this broke every CI job but Node 22 and Bun on 2026-10-14).
- **QUIC provision:** an N-API addon over a vendored copy of `switchboard_quic/native/sbq` with one change (`"rlib"` in the crate types), byte-identical otherwise and separable; the pin outside the copy (`native/sbq-vendor.commit`); a shared shim repository is the intended later direction. No upstream change.
- **Browsers:** `webTransport(init?)` returns the provider (a `QuicConnector`); `webTransportConnector(url, init)` returns a `ReconnectingClient`'s connector.
- **Placement:** `MeshNode` and `PeerSet` in `core/switchboard/`; `SlotGate`, `SlotLifecycle` and `SlotGates` in `core/naming/slot-gate.ts`; `isSlotResolver` in `core/switchboard/resolver.ts`; `StaticResolver` is a `SlotResolver`.
- **Binding base** keeps Dart's scope (drain holds, neutral diagnostics); the identity exchange and the two hooks are each binding's own. `_bulk` routing is installed by Talk through `adoptIncoming` and `admitAfterGoAway`.
- **Idioms** (design section 5): `Uint8Array` bytes, numbers for u48 ids, ms durations, const objects, pull-based `AsyncIterable` delivery with credit on delivery, Web Streams, typed `Emitter`, `AbortSignal`, `Symbol.asyncDispose`, injectable `Clock` and `Logger`, WebCrypto, `SwitchboardError` and `ProtocolError`, `RangeError`/`TypeError` for misuse, plain `Error` for `StateError`; wall time in ms for credentials and `verifyIdent`.
- **Taken in the review round** (design section 11; the reports have the arguments): the channel contract (`send`, `open`, `openAfter`, a channel's `writable`) takes `Uint8Array` only and throws `TypeError` for anything else on both bindings (`checkMuxBytes`), where Talk and above keep `PayloadLike`; the receive pause's accounting is unchanged (every channel counts what it buffers unread, the ended ones included, as the wiki and Dart have it), `close()` of an ended channel nobody reads releases its bytes (design 12.19), and the wider concern is the user's (13.10); the TS bindings make the same choices as the Dart shutdown fix (the PING barrier, the 2 s hold; the wiki text is final at Sway `1947ac37`), so they are no deviation; credential expiry reads one wall clock (`MuxOptions.wallTime`, defaulting to the verifier's) and the in-process pairs of a node run on its clock (`SwitchboardRuntime.transportPair(clock)`), the two contract changes of the round; the exporter label constants take Dart's names.
- **Branches:** `main` is the integration branch (the first hand-off's open question is closed).

## 6. Conventions

- **Worktrees and branches:** one topic per branch `claude/<topic>`, in a worktree `/home/user/wt/<topic>` branched from `main`; never edit the main checkout or commit on `main` from a worktree. Push only your own branch (`git push -u origin claude/<topic>`, retrying with backoff on network errors); the lead merges into `main` and pushes it.
- **Merges:** real merge commits only (`git merge --no-ff claude/<topic>`), never squash or rebase; keep branch history granular; continue a merged branch from `main` with a merge. The lead's procedure: merge, resolve conflicts, `npm run check`, `npx tsc -p tsconfig.test.json --noEmit`, push.
- **Commits:** one per milestone, a descriptive subject, a body saying what and why, and the two trailer lines `Co-Authored-By: Claude <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01B2KoRQTAdtpnxcxjhmD2ey`; no model names or identifiers anywhere (commits, code, comments, docs); nothing about hosts, credentials or internal paths in commit messages.
- **Adversarial review, then fix** (design section 9): a reviewer who did not write a layer reads it against the Dart sources, the design and the wiki, and writes a failing test per finding as `test.fails` (the suite stays green; once the defect is fixed the test fails until the `.fails` goes), with a report `docs/notes/review-<layer>.md` (findings by severity with file and line, the path to the defect, the test, the fix and what Dart does; then unverified suspicions and what was surprising but fine). A fix agent on the same branch fixes one finding per commit, drops the `.fails`, records the status in the report, lists deviations from Dart in design section 12 and questions for the user in section 13. Suspicions nobody could reproduce are not tests: they go to the layer's `docs/notes/<layer>.md`. The lead merges after `npm run check`, the test typecheck, the native QUIC files and, for anything near the wire, the interop matrix. No `test.fails` is left in the tree.
- **Caller bytes, promises, signals:** copy a caller's bytes with `new Uint8Array(x)` or `Uint8Array.prototype.slice.call(x)`, never `x.slice()` on a value that may be a Node `Buffer` (a view on shared memory); reject through a `Deferred` (or pre-catch) wherever the caller may drop the promise; every call that waits takes an `AbortSignal` and rejects with its reason; validate options where they are merged, before anything is dialled (`RangeError`).
- **Before handing a branch over:** `npm run check` and `npx tsc -p tsconfig.test.json --noEmit` clean; the projects relevant to the change run often while working.
- **Style:** Biome (single quotes, 100 columns), `.ts` import extensions, `type` imports, no `any`, no TS `enum`, no `biome-ignore` without a reason, the file header comment as in the sources, JSDoc on every export, `process.env['X']`.
- **Ownership:** contract files (`src/core/*/contract.ts`) and the barrels outside a topic's directories are the lead's; a contract change goes in its own commit with a rationale. Stay inside the files a task names; shared test helpers go under `test/support/<area>/`.
- **Tests:** never skip, disable or weaken a test to get green; name TS test files after the Dart files; register wiki vector ids through `test/support/vectors.ts`.
- **Dart repositories are read-only.** Findings about them are reported (in notes and to the lead), never patched here.
- **Naming test doubles:** by what they are or do, never by their status as stand-ins (`Memory*` for an in-memory implementation of a contract, an adjective for a double defined by one behaviour); no catch-all labels for doubles in code, comments or documents, "stub" is fine, and time a test controls is virtual time. Design section 9 states the rule; the Dart repositories share it and the names (`switchboard-ts/naming-map.md` in the project files).
- **Docs:** keep `docs/design.md`, `docs/work-split.md`, this document and `docs/wiki/` in step; wiki pages are GitHub wiki Markdown with relative page links (`[Identity](Identity)`), and every code block in them type-checks against the built package.
